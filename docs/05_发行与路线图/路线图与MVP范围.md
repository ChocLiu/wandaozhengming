# 路线图与 MVP 范围

> 状态：初稿 v0.2 · 2026-08-30
> 总原则：**先深后宽**——3 个机制做深 > 30 个机制做浅。每阶段只验证一个假设，验证不过就回头改设计，这就是「用 Godot 试水」的意义。

**阶段定义（内测 / 公测之分）**：
- **P0 原型阶段 = 纯内测**：只给开发者自己与少数熟人试玩，**不公开、不上架**——此阶段世界观可以不完整，只验证机制假设
- **公开露脸门槛**（商店页 / Demo / 新品节）：核心循环成立 + **世界观完整成型**（道之树、时代快照、势力金字塔、种族全部定稿）——世界观是公测的门槛，不是原型的门槛
- **公测 / EA 发售**：完整世界观 + 稳定核心循环 + 充足内容

---

## P0 · 战斗原型（约 4~8 周，solo）

> 状态：**进行中**（2026-08-30 开工）。已完成：工程骨架、最小战斗内核（ATB/部位/四池/双维命中/破防）、最小战棋（移动+射程）、武侠叙事解说、成语修为量表、**挂载体系**（主修槽/招式槽/切换/普攻随机+招式面板/招式冷却/武器修正/有界属性层）。剩余：大招与散招、功法机制脚本化（剑意等）、回放器、GUT 单测。

**目标：验证核心乐趣假设 H1/H2/H4**（机制差异、组合涌现、博弈乐趣——见《游戏定位与设计支柱》§7）。

### 范围（最小可玩）
- **1 个种族**：人族
- **3 门功法**：青莲剑歌（剑·状态面）、太虚阵经（阵·场地面）、焚天诀（火·资源面+场地面）——选机制差异最大的三门
- **主辅组合**：主修 1 + 辅修 1，接口匹配检查 + 1 个共鸣（太虚剑阵）
- **战斗框架**：10×10 格、ATB 进度条（仙三式）、最小战棋（回合内移动+招式射程）、部位系统与要害（凡人~金丹三层部位结构）、战斗四池（气血/体力/玄力/魂力）、速度对抗+规则对抗与破防结算、武侠叙事解说、成语修为量表、六子系统最小实现
- **无剧情、无美术**：方块占位、文字 UI（只做战斗，不做世界）

### 明确不做
- 不做任何种族差异、不做自创（L1 嫁接即主辅组合，天然自带）、不做成长经济、不做地图
- 不做完整境界要害阶梯（P0 只做 凡人~金丹 三层部位结构，化神+ 的神魂击杀规则后置）
- 不做世界内容落地（道之树其余分支只存在于文档；世界观文档与原型并行推进，互不阻塞）

### 验收标准
- [ ] 剑修、阵修、焚天三者玩法手感完全不同（玩起来像三个游戏）
- [ ] 能做出一个**策划文档里没写过的组合**，且它能赢
- [ ] 一场斗法全程有决策点，无「闭眼点攻击」时刻
- [ ] **无总血条成立**：能通过「击毁丹田/识海」而非「打空血条」获胜
- [ ] 战斗可回放、可 headless 自对弈（技术验收）
- [ ] **不好玩就回炉**——这是原型阶段唯一的目的

## P1 · 垂直切片（约 3~6 个月）

**目标：验证 H3（悟道成长循环的动力感），产出可公开宣传的切片。**

### 范围
- 人族完整修途：凡境→灵境，寿元/死亡三途/机缘/感悟闭环
- 一张小地图 + 一个门派 + 3~5 个有名字的 NPC（拜师、讲道、切磋；宗门阶梯：外门→内门→真传）
- 功法获取循环：拜师/机缘/感悟/抢夺（含因果寻仇）
- L1 嫁接正式化 + L2 推演（1~2 个可改参数的功法）
- 美术风格确立（主角/NPC/战场/UI 一套完成度稿）
- **同期启动 Steam 商店页**（见《Steam发行策略》）

### 验收标准
- [ ] 没有经验条的情况下，玩家仍有持续游玩动力（H3）
- [ ] 世界观完整版定稿（道之树/时代快照/势力金字塔/种族细化完毕）——公开露脸的前置条件
- [ ] 可拍摄一段 60 秒宣传片（战斗机制展示 + 修炼成长）

## P2 · 核心扩展（EA 前）

**目标：验证「混血+杂道」与「世界是活的」。**

- 第二种族（妖族）+ 混血血脉 + 冲突/杂道系统
- 功法库扩到 12~15 门，共鸣表扩充
- L2 推演完善；世界动态：灵潮事件、势力声望、NPC 修炼
- 圣子/圣女继位竞争雏形（论道大会、宗门声望）
- 第二张地图区域

## P3 · EA / 正式版

- **L3 立道编辑器**（元件库拼装）+ 证道 + 世界功法库 + 开宗立派
- 更多种族（鬼/魔/灵/器/巫/神逐个加入，每个 = 一个玩法模块）
- 主线剧情（遁去的一、巫道失落、妖灵道补全）
- 内容填充：秘境、渡劫、事件池

> **长期愿景**（正式版之后，不承诺时间）：上界之梯（合道一域=域主之争、破域飞升的诸天万域）、时间长河穿越玩法（每个时代一个完整世界快照，见《世界观设定》§6）、隐藏种族解锁。

## 砍功能原则（立项级约定）

1. **每阶段只有一个验证假设**——凡是不服务当前假设的功能一律砍
2. **机制优先于内容**：先做深 3 个机制，再想 30 个机制的清单
3. **内容可外包/后期填，机制必须亲手验证**：数值、文案、美术量都可以后补，核心循环不好玩是死刑
4. 新功能提案必须过《游戏定位》的红线检查单
